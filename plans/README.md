## Dependency notes

- **002 requires 001** because mobile filtering (local `CategoryStartTimes`) is correct by itself, but the ideal UX (no empty tabs, no waktu-start phantom) comes from server already omitting empty categories. 002 works standalone via fallback that derives categories from `participants.distanceCategory`, but implementing 001 first removes the need for that fallback to be load-bearing and keeps client/server consistent.
- **003 requires 002** because gender tabs are nested inside category tabs. If category tabs are still hard-coded to `['5K','7K','10K']`, adding gender split produces phantom sections like `20K - Laki-laki` kosong. 002 makes `categoriesProvider` dynamic, which 003 consumes as the outer `TabBar` length.

Recommended order: 001 → 002 → 003. If backend cannot be deployed before mobile, 002 may be executed first via its fallback path, but 001 must still land before release to avoid server/client drift.
